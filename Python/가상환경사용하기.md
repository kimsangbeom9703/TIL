# [Python] 가상환경 사용하기 (venv)

## 가상환경이란
```
    프로젝트마다 파이썬이랑 패키지를 따로 쓰는 독립된 공간이다.

    컴퓨터에 깔린 파이썬(전역)에 pip install 을 하면
    모든 프로젝트가 같은 패키지를 공유한다.

    A 프로젝트는 Django 4, B 프로젝트는 Django 3 이 필요하면
    한곳에 설치할 수가 없다. 버전이 충돌난다.

    그래서 프로젝트 안에 venv 폴더를 만들고
    그 안에서만 패키지를 설치해서 쓴다.
```

## 사용하는 이유
```
    1.  패키지 버전 충돌을 막는다.
        전역에 설치하면 다른 프로젝트까지 영향이 간다.
        venv 안에서 설치하면 그 프로젝트에만 설치된다.

    2.  프로젝트마다 필요한 패키지만 관리할 수 있다.
        나중에 서버에 올릴 때도 requirements.txt 만 있으면
        똑같이 맞출 수 있다.

    3.  전역 파이썬을 더럽히지 않는다.
        테스트하다가 패키지가 쌓이면 뭐가 뭔지 모른다.
        venv 폴더만 지우면 깨끗해진다.

    4.  따로 프로그램 설치가 필요 없다.
        파이썬 3.3 부터 기본으로 들어있다.
        pip install 할 필요 없이 python -m venv 로 바로 만든다.
```

## venv 로 만드는 방법

### 1. 프로젝트 폴더로 이동
```
    mkdir myproject
    cd myproject

    보통 프로젝트 폴더 안에 venv 를 만든다.
    프로젝트랑 환경을 같이 두는 게 편하다.
```

### 2. 가상환경 만들기
```
    python -m venv venv
        -   venv 라는 폴더가 생기고 그 안에 파이썬이 복사된다.
            폴더 이름은 아무거나 해도 된다.
            보통 venv 또는 .venv 로 만든다.

    리눅스에서 python 이 안 먹으면
        python3 -m venv venv

    만들면 대략 이런 구조가 된다.
        myproject/
            venv/
                Scripts/        // Windows  실행 파일
                bin/            // Linux / Mac
                Lib/
                pyvenv.cfg
```

### 3. 가상환경 활성화
```
    Linux / Mac
        source venv/bin/activate

    Windows
        .\venv\Scripts\activate

        PowerShell 에서 실행이 막히면
            Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
            한 번 허용해 주고 다시 activate

    활성화되면 프롬프트 앞에 이름이 붙는다.
        (venv) PS C:\ksb_project\python\myproject>
            이게 보이면 가상환경 안이다.

    활성화 안 하고 pip install 하면 전역에 설치된다.
    무조건 (venv) 붙어있는지 확인하고 작업한다.
```

### 4. 패키지 설치
```
    * 가상 환경에서 실행

    python -m pip install --upgrade pip     // pip 먼저 업데이트
    pip install django
    pip install fastapi

    설치확인
        pip list

        where python        // Windows      지금 쓰는 파이썬 경로
        which python        // Linux / Mac
            venv 경로가 나와야 정상이다.
```

### 5. requirements.txt 로 관리
```
    다른 환경에 세팅할 때 pip list 보고 하나하나 설치하면 귀찮다.

    저장하기
        pip freeze > requirements.txt
            현재 설치된 패키지를 파일로 저장

        ex)
            asgiref==3.7.2
            Django==4.2.4
            sqlparse==0.4.4

        django==4.2.4   // 해당 버전
        django>=4.2     // 이상
        django          // 최신 버전

    설치하기
        pip install -r requirements.txt
```

### 6. 비활성화 / 삭제
```
    비활성화
        deactivate
            프롬프트 앞의 (venv) 가 사라진다.

    삭제
        venv 는 그냥 폴더다.
        폴더 지우면 환경도 같이 사라진다.

        Linux / Mac
            rm -rf venv

        Windows
            rmdir /s /q venv
            또는 폴더 자체를 삭제

        다시 만들면 된다.
            python -m venv venv
            활성화 후 pip install -r requirements.txt
```

## 주의할 점
```
    1.  venv 폴더는 git 에 올리지 않는다.
        .gitignore 에 넣는다.
            venv/
            .venv/

        올리는 건 requirements.txt 다.
        받는 사람은
            python -m venv venv
            활성화
            pip install -r requirements.txt
        하면 된다.

    2.  활성화 안 하고 pip install 하지 말 것.
        전역에 깔리면 나중에 뭐가 꼬인다.

    3.  IDE 인터프리터를 venv 파이썬으로 잡아줘야 한다.
        VSCode / Cursor
            Python: Select Interpreter
            venv/Scripts/python.exe     // Windows
            venv/bin/python             // Linux / Mac

        이거 안 하면 에디터는 전역 파이썬을 보고
        터미널은 venv 를 봐서 패키지를 못 찾는 일이 생긴다.
```

## 한줄 정리
```
    venv = 파이썬 기본 가상환경
    만드는 이유 = 패키지 충돌 방지 / 프로젝트별 독립 / 배포 재현
    쓰는 순서 = python -m venv venv -> 활성화 -> 패키지 설치 -> requirements.txt -> 작업 -> deactivate
```
