# Cursor를 선택한 이유

> **요약**: AI는 Cursor만 쓴다. VSCode 기반이라 개발이 편하고, 예전에 쓰던 JetBrains는 비싸고, Claude는 터미널에서 써야 해서 결국 다른 IDE가 또 필요해서.

## 1) 개요

**"에디터 따로, AI 따로 쓰기 싫다"**

- **지금 쓰는 것**: Cursor AI만
- **예전에 쓰던 것**: JetBrains (비싸서 그만둠)
- **안 쓰는 것**: Claude (터미널에서 써야 함 → IDE를 따로 써야 함)
- **선택 기준**: AI가 얼마나 똑똑한지보다, **지금 쓰는 개발 환경에서 바로 되느냐**

---

## 2) Cursor를 쓰는 이유

```
제일 큰 이유는 이거다.

Cursor는 VSCode 기반으로 만들어져 있다.
그래서 개발이 너무 편하다.

- 원래 VSCode 쓰던 단축키, 확장, 터미널, git 그대로 가져온다
- 에디터 안에서 파일 수정, 실행, 디버깅이 다 된다
- AI한테 물어보는 것도 같은 화면에서 끝난다

코드를 짜려면 결국 IDE가 필요하다.
AI가 아무리 좋아도, 작업하는 곳이 불편하면 의미가 없다.

나는 에디터에서 바로 개발하면서 AI를 쓰는 쪽이 맞다.
그래서 Cursor만 쓴다.
```

---

## 3) JetBrains를 안 쓰는 이유

```
그전에는 JetBrains를 썼다.

기능은 좋다.
대신 너무 비싸다.

라이선스 끊고 나면 그냥 못 쓴다.
팀/회사 아니면 개인이 계속 유지하기 부담된다.

Cursor는 VSCode 기반이라 익숙하고,
개발에 필요한 건 그걸로 충분하다.
돈 더 내고 JetBrains 쓸 이유가 지금은 없다.
```

---

## 4) Claude를 안 쓰는 이유

```
Claude도 좋긴 하다.
근데 나는 터미널에서 Claude를 쓰는 방식이 안 맞는다.

Claude를 쓰려면
- 터미널에서 명령을 쳐야 하고
- 코드 보고 고치는 IDE는 따로 있어야 한다

그러면 결국 또 다른 IDE를 써야 한다.
JetBrains를 다시 켜든지, VSCode를 따로 켜든지.

나는 그게 싫다.
창을 왔다 갔다 하면서
터미널에 물어보고, IDE에서 다시 확인하고...
그 과정이 오히려 느리다.

Cursor는 IDE 안에 AI가 붙어 있으니까
물어보고 바로 파일을 고친다.
이 차이가 크다.
```

---

## 5) 그래서 효율이 나는 이유

```
효율은 "AI가 코드를 잘 짜줘서"가 아니다.

작업 공간이 하나라서 빨라진다.

- 에디터 / 터미널 / AI가 한곳
- 복붙해서 다른 창에 옮길 일이 없다
- 파일 경로, 프로젝트 구조를 매번 설명할 필요가 적다
- 고친 다음 바로 실행해보고 다시 물어볼 수 있다

Claude + 다른 IDE 조합은
생각 → 터미널 → IDE → 다시 터미널
이 루프가 생긴다.

Cursor는
생각 → 같은 화면에서 수정 → 실행
이걸로 끝이다.
```

---

## 6) 실제 작업 흐름

```
1. Cursor에서 프로젝트 연다
2. 뭘 만들지 짧게 말한다
3. 파일 생성 / 수정은 에디터 안에서 바로 한다
4. 터미널에서 실행하고 에러 보면 그 자리에서 다시 고친다
5. 동작하면 내가 한 번 더 읽는다
6. 나중에 까먹지 않게 TIL에 남긴다
```

---

## 7) 정리

```
Cursor를 쓰는 이유는 단순하다.

VSCode 기반이라 개발이 편하다.
JetBrains는 비싸다.
Claude는 터미널에서 써야 해서 IDE를 또 써야 한다.

나는 AI를 따로 쓰는 게 아니라
개발하는 그 화면에서 AI를 쓰고 싶다.

그래서 Cursor AI만 쓴다.
```
